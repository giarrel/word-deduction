# Session interface

`game/Assets/WordDeduction/Session` is the deep, Unity-independent module for the saved group. Callers open `Session.Open(directory, initialLanguage)`, issue a user action, then obtain `Session.View`. UI code never changes persistent DTOs. View instances are detached copies. The initial locale applies only when no saved state exists.

Actions: add, rename, set participation, remove, undo the last removal, select language/mode, and explicitly start fresh after unrecoverable damage. `CommandResult.Success` means the complete state was saved before the in-memory state changed. `Error` and `Notice` are stable localization keys, not text for direct display. A failed save leaves previous memory and disk intact and can be retried. Invalid/stale player IDs are rejected.

Names are trimmed and NFC-normalized, 1–24 Unicode text elements, without control characters. Stable IDs are independent of names. Duplicate names retain durable numeric disambiguators; entering a name equal to a generated label is also disambiguated. Twenty people may be active; additional saved people begin paused, with `AddedPaused`. Forty people may be saved. Undo restores identity, order and participation unless a current capacity limit prevents it.

The JSON envelope has `Version`, `Payload` and SHA-256 `Checksum`. Both checksum and group invariants are validated. Each write flushes a pending file, then atomically replaces primary and previous generation. Pending files are never treated as confirmed actions. A damaged primary may recover a valid previous generation; the view exposes `RecoveredBackup`. Both invalid generations block mutation and expose `DamagedData`; explicit fresh start first archives the damaged files. A newer schema exposes `NewerVersion` and cannot be reset by this app. Read permission/IO errors expose `ReadFailed` without overwriting files.

Android uses the application's internal files directory; the Editor uses a dedicated subdirectory of Unity's `persistentDataPath`. `link.xml` preserves the JSON DTOs for IL2CPP. The serializer is Unity's `com.unity.nuget.newtonsoft-json` package. The .NET behavior runner compiles the same source and references that exact resolved Newtonsoft DLL. By default, run Unity's initial import first; an already resolved DLL from another checkout can instead be passed with `-p:NewtonsoftJsonAssembly="<absolute path to Runtime/Newtonsoft.Json.dll>"`. This overrides only the reference path, not the production sources under test.

Match actions and safe projections are also owned by Session. `StartMatch` and `Rematch` snapshot participants, roles, language and concrete words before reporting success. Revealing is an explicit, volatile action; opening a saved match never reveals or redraws it. See the match implementation and validation reports for mode transitions.

V4 stores the pair draw history with the same atomic snapshot as a new deal. All 520 bilingual pairs in `content/word-pairs.json` are compiled into the Session assembly; `content/compile-catalog.cjs --check` checks their exact correspondence. One shuffled pair-ID cycle is shared by both languages. Recent words are compared in both languages using the last ten deal IDs, but exhausting the cycle takes precedence over word avoidance. Failed starts/rematches do not consume history; successful deals remain consumed even if subsequently abandoned. V1–V3 migration seeds an existing match's ID as consumed without changing or rewriting the deal on open. History never appears in safe match views.

`ReadyToStart` describes group-size validity. Quick and Classic share `StartMatch`, private reveal/conceal/advance, clue-round voting, confirmation, result and rematch actions. The Session owns all rules; presentation reads the detached `Match` view and never computes winners.

Classic adds saved `WhitePreferred` and effective group counts, `Match.Survivors`, `Round`, an eliminated role in `Elimination`, and `ContinueRound(expectedRound)` / `ResolveWhiteGuess(expectedParticipantId, correct)`. No private words appear in ordinary views or elimination/guess screens. `RevealWord` deliberately returns `Mr. White` only for that private role card; the UI supplies its localized bluffing instruction. The role's guess is spoken and judged by the group, never compared as typed text.

V4 retains the V3 migration of V1 groups and V2 frozen Quick deals. Missing progress fields default to round 1 with no eliminated participants. Existing phase values 0–3 retain their meaning; Elimination 4 and WhiteGuess 5 are appended. Opening old data does not write or redraw. All writes still use the same atomic transaction. Newer versions remain blocked before corruption recovery.

`Result.WinningRoles` is the complete winning set. A correct White guess yields only White; one surviving Civilian yields the roles of living adversaries (Undercover, White, or both). `Winner` remains the first role for Quick-compatible callers; multi-role presentation must use `WinningRoles`. Pending White guesses are persisted before any terminal check. Eliminations affect the frozen match only, leaving the saved group's participation untouched.

## Kings foundation (ticket #12)

`GameMode.Kings` is appended as value 2. `SetMode` selects it with the existing saved Group; `ReadyToStart` requires 5–20 active players. All modes use the same strict initial good-majority policy: ordinary Undercover plus Whites are fewer than Civilians. This is configuration validity only, never a live-match victory check.

`SetKingsUndercoverPreference(int?)` sets the ordinary-Undercover count; `null` restores the adaptive existing Classic defaults. An explicit number outside 1 through `View.KingsUndercoverLimit` is rejected with `InvalidSetting`, without replacing the prior preference. `View.KingsUndercoverPreference` retains a valid requested number when the group shrinks; `UndercoverCount` is the clamped effective value and `KingsCountAdjusted` lets presentation explain the difference. Increasing the group restores the requested count. Kings always deals one additional White and one good King; it does not consume or change Classic's `WhitePreferred`. Running matches freeze all settings.

`RevealCard(ownerId)` is the owner-scoped private projection for all modes. It has a detached `Owner`, optional `Word`, neutral `Kind`, optional `Leader` and `KnownParticipants`. Kings ordinary Civilians and Undercover both have `Kind.Word`, their own word and leader, and no known-name list or side property. `GoodKing` has the good word and an unmarked evil-name set in frozen participant order. `EvilKing` is White, has no word and knows only ordinary teammates. Nested known participants contain only stable identity and display name. They do not expose roles, King flags, words, or associations. `RevealWord` remains an old-mode-compatible narrow adapter, returning the word or the established `Mr. White` marker.

The existing reveal/conceal/advance contract applies to the whole card. Covering and reading the current unfinished handoff again is allowed; `AdvanceHandoff` durably consumes it, rejecting earlier owners after restart. `HideWord` clears the volatile reveal state for the entire projection. There is no timer. Failed commits keep the current handoff and the original deal. Reopening never redraws or restores a revealed screen.

`MatchPhase.TablePlay` is appended as value 6. After the last Kings handoff, it exposes public participants/survivors with no owner, starter, elimination, result, leader, or per-side survivor counts. Quick/Classic voting actions do not accept this phase. Ticket #12 provides its compact survivor landing; direct elimination and last-chance progression belong to tickets #13/#14, and complete help/readability acceptance to #15.

The envelope now writes V5. V1–V4 groups and valid frozen Quick/Classic matches still open without rewriting, rerolling, or resetting IDs, accepted Unicode names, undo, language, White preference, or word history. Existing enum values are unchanged. V5 stores the optional Kings count and frozen good-King ID; the single saved White assignment identifies the evil King. New data in a pre-V5 envelope is rejected. Newer schemas remain blocked in either committed generation. All changed settings and handoffs use the existing atomic transaction and backup/recovery policy.

In the rendered app, Kings adds one mode button and a bounded minus/plus count control with an Auto reset and explicit retained-preference adjustment text. Secret leader/name labels live only beneath the already-excluded `cardDrag` subtree, are cleared synchronously on cover, and never enter any level of the public accessibility hierarchy. Longer private lists use the private scroll viewport; continued upward movement of the same reveal finger scrolls it, with release still concealing everything. Final small-phone, maximal-name, large-text and native acceptance remain part of the later tickets.

## Kings elimination (ticket #13)

`SelectElimination(matchId, eliminatedCount, participantId)`, `CancelElimination(matchId, eliminatedCount, participantId)` and `ConfirmElimination(matchId, eliminatedCount, participantId)` are Kings-only commands. The eliminated count is `Participants.Count - Survivors.Count` from the caller's detached view. Match identity, progress, phase and selected target are checked before mutation. Selection and cancellation are saved; only successful confirmation removes the participant and exposes its consequence. A failed save preserves the preceding safe projection and can be retried.

Ordinary confirmation enters appended `KingsElimination` (7). Its only elimination projection is `EliminatedParticipant`, a public ID and display name; the phase means “Not a king.” The Classic `Elimination` role projection stays null. This surface directly accepts the next actual elimination through the same select command; it requires no continue, clue-round, vote or tie action. Selecting the next person replaces the previous notice with a correctable pending selection in `TablePlay`.

Confirming the good King immediately produces `GoodKingEliminated`; confirming the last ordinary survivor produces `OnlyKingsRemain` when exactly the two Kings remain. Both results include Undercover and White in `WinningRoles`, including eliminated teammates. `Result.Roles` retains every participant and marks the two Kings with `IsKing`. Both words and all assignments appear only in `Result`. Rematch and return-to-group keep the existing saved group/settings/history behavior. Numerical parity and a lone good King with other survivors remain live states.

Confirming White instead enters appended `KingsLastChance` (8), durably retaining White as the eliminated participant and exposing no result, role assignments, good King or words. Ordinary table actions and Classic White judgment reject this phase. Ticket #14 extends this entry with the binding choice and attempt; #13 deliberately provides no shortcut to a judgment or result. Persisted Kings states remain part of the unreleased V5 schema introduced by #12; existing enum values and Quick/Classic states retain their meaning.
